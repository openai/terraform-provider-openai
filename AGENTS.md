# Contributor instructions

## Terraform provider implementation guidelines

- This repository publishes the `openai/openai` Terraform provider and its
  signed release artifacts. Preserve provider behavior, Terraform Registry
  compatibility, and the release process described in
  [RELEASING.md](RELEASING.md).
- Treat files listed in `.terraform-generator-manifest.json` and files marked
  `Code generated by generate-terraform-provider. DO NOT EDIT.` as
  generator-owned. This includes much of `internal/provider/`, `docs/`,
  `examples/`, `templates/`, the Go module files, and CI configuration.
  Coordinate changes with the generator owners instead of hand-editing
  generated output.
- `make generate` runs `tfplugindocs` through `tools/` to regenerate
  Terraform Registry documentation; it does not regenerate the provider
  implementation. Regenerate documentation only when the change requires it.

## Security requirements

- Never commit real API keys, access tokens, signing keys, credentials, private
  certificates, or customer data. Load the provider's Admin API key from
  `OPENAI_ADMIN_KEY`, and use clearly fake values in examples, tests, and
  fixtures.
- Preserve `Sensitive: true` for credential-bearing Terraform schema
  attributes such as `admin_api_key`. Never put live credentials or customer
  data in Terraform state, plans, outputs, `.tfvars` files, examples, or
  generated documentation.
- Redact authorization headers, cookies, tokens, signed URLs, credential-bearing
  query parameters, organization/project identifiers, customer data, and
  sensitive request/response bodies from logs, diagnostics, crash reports,
  `TF_LOG` output, fixtures, and CI artifacts.
- Review direct and transitive dependency changes in `go.mod`, `go.sum`,
  `tools/go.mod`, and `tools/go.sum`, including module sources, `replace`
  directives, checksums, generator/tooling changes, and install/build scripts.
  Review provider sources and checksums in `.terraform.lock.hcl` when a
  contributor configuration includes that file.
- Pin third-party GitHub Actions to full commit SHAs. Preserve least-privilege
  workflow/job permissions, keep credentials away from untrusted pull-request
  code, and use `persist-credentials: false` when checkout does not need a
  persisted token.
- Protect GitHub App private keys and release credentials, including
  `OPENAI_SDKS_APP_PRIVATE_KEY`, `GPG_PRIVATE_KEY`, and `PASSPHRASE`. Keep
  release automation and signing credentials scoped to the protected
  `release` and `publish` environments; never expose or broaden them for
  ordinary CI.
- Preserve the provider release archives, GPG-signed checksum manifest,
  per-archive SPDX SBOMs, Terraform Registry manifest, release-tag integrity,
  and the release SBOM verification gate.
- Request maintainer or `@openai/sdks-team` review for changes affecting
  authentication, `base_url`, redirects, TLS, organization/project isolation,
  Terraform schema/state, resource import, path/query serialization, logging,
  dependencies, generated code, or CI/release behavior. Add focused regression
  or security tests for the affected boundary.
- Never run `TF_ACC=1`, `make testacc`, or related acceptance-test targets
  without explicit authorization and scoped disposable credentials; these tests
  can mutate real OpenAI organization resources.
- Report suspected vulnerabilities in the provider or its release artifacts
  privately as described in [SECURITY.md](SECURITY.md), using
  `disclosure@openai.com`. Never disclose vulnerabilities through public
  GitHub issues, pull requests, or discussions.
